# Case specs

One JSON per case: `data/cases/<case_id>.json`. Generated by `analysis/make_cases.py` (inputs and sources live
there) and checked by `analysis/build_targets.py`. Edit the generator, not the JSON.

    python analysis/make_cases.py      # writes all case files (keeps existing case_id, diagnosis, test_name)
    python analysis/build_targets.py   # recomputes every target with analysis/bayes.py, asserts match to 1e-9

## Id scheme
`<set><n>_<name>_<pos|neg>`. Scenario = id without the suffix (`A1_pneumonia`), `result` = `pos` or `neg`.
Set A: A1 pneumonia (chest radiograph), A2 breast cancer (mammography), A3 cardiac ischemia (exercise stress
test), A4 UTI/bacteriuria (urine culture), A5 numeric hypothetical (condition V only). Set B: B1 PE low Wells
(D-dimer), B2 PE moderate (CTPA), B3 PE high (CTPA), B4 acute aortic syndrome (D-dimer), B5 appendicitis (CT),
B6 appendicitis (ultrasound).

## Fields
`case_id, scenario, set, result, diagnosis, setting, patient_summary, test_name, result_shown, pretest_source,
status ("VERIFIED"/"PROVISIONAL"), unverified [..], sources [{quantity, citation_key, id, location, status}],
conditional_independence, target_inputs, target, notes, exclude_from_fit, sensitivity_priors`.
`target` (all probabilities in [0,1]): `pretest_point, pretest_range, lr_point, lr_range (LR for the result shown),
posttest_point, posttest_band_primary, posttest_band_bayes`. Targets never appear in notes or prompts.
Each case applies one LR to one prior, so no conditional-independence assumption is used; the file states it
anyway, and any combination of LRs would assume conditional independence given disease status.

## How targets are computed (build_targets.compute)
- Prior: `logodds_midpoint` of a printed range (expit of the mean logit of the endpoints), or a stated point.
- LR: `geomean_range` (sqrt(lo*hi)), `published_point`, or `from_sens_spec` (LR+ = sens/(1-spec),
  LR- = (1-sens)/spec; labelled computed, not published).
- `posttest_point = bayes.posterior(pretest_point, [lr_point])`.
- Set A `posttest_band_primary` = printed Morgan Table 3 posttest range; `posttest_band_bayes` = min/max
  of Bayes over the four corners of the pretest range x LR range. Set B primary = Bayes over the published LR
  CI/range at the point prior where one exists, else degenerate at `posttest_point`; Bayes band equals primary.
- Zero endpoints and the A5 hypothetical (LR- = 0): see in.

## Status
Set A (A1 to A4, A5) numbers are VERIFIED against Morgan 2021 PMC8022260 Tables 3 and 4 and the Results text
. Morgan eAppendix 2 (sens/spec behind the evidence ranges) was not seen, but no
case number depends on it. Set B (B1 to B6) is VERIFIED against the full-text PDFs in data/sources/;
case-level caveats (different cohorts for prior and LR) are in each file's `notes`. PE cases carry `sensitivity_targets`
(PIOPED II observed PPV/NPV). Nothing PROVISIONAL may appear as a final number in the paper.

## Condition E removed-item classification (F5, committee #6)
`meta/E_removed_classification.json` (kept in a subfolder because `data/cases/*.json` is globbed as case files; generated by `data/notes/classify_e.py`; do not edit by hand) lists, per case
(pos and neg), every pertinent negative removed in condition E with the N-note wording, and flags whether it is
a component of the score or definition behind the case's prior: `basis` = "score item" (Wells for B1 to B3,
ADD-RS for B4, Alvarado for B5 and B6), "vignette definition" (a negative stated in the Morgan 2021 vignette:
A2 average-risk asymptomatic screening, A3 no cardiac risk factors, A4 no urinary symptoms, which separates UTI
from asymptomatic bacteriuria), or "none" (ROS lists and other negatives this study added). `other_relevance`
notes items that matter for another reason without being score items (B5/B6 no prior abdominal surgery and
the urinalysis). A1 removes only study-added negatives. The script asserts that it covers every item in
`render.E_SPEC`. The classification is a case-builder judgment (in
); the analyst reports H4 by group from it.
